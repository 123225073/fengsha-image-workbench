# 上下文与联网检索修复（1.1.0）

2026-11-13，本地版本，未发布 GitHub。

## 已确认的原因

- PPT 请求只携带最后 4,000 个字符，搜索补充只取最近四条；通用对话后端只读最近 16 轮。模型支持长上下文也无法看到应用未发送的内容。
- 海报沟通还会把前端记录裁到最近 12 轮，检索上下文与回答上下文使用不同的截断。
- 搜索关键词由正则截取最新一句话，实际数据库记录中的检索词是“主要是这两个项目的一个对比分析”。没有先解析“这两个项目”的指代。
- 提供的 GitHub 地址没有直接作为阅读入口；相关性判断使用了错误主题，于是把“主要”的词典释义误判为相关来源。
- PPT 提示词要求每轮复述目标并追问，进一步造成了没有推进对话的感觉。

## 现在的流程

完整会话记录 → 按容量组织模型上下文 → 用当前语言模型规划少量检索词 → 优先读取用户链接 → 按对象补充搜索 → 相关性和版本过滤 → 必要时使用第二搜索服务 → 读取正文 → 带来源与缺口回答。

指定 GitHub Release 会读取该版本的发布说明和 README；不会用 main 分支冒充指定版本。多对象比较保留每个对象的来源名额。失败链接不会显示“已读取正文”，没有相关证据不会显示成功。

模型规划最多一次，格式错误或明确拒绝可回退到规则方案，结果不明的付费调用不重试。规划和回答用量合并计费；缺少用量仍待核对。复用证据不额外规划。

原始聊天和工作区数据继续保留。预算内原文直接传入；超预算保留近期完整对话，以及较早相关要求、链接和纠正的原文节选，并明确告知模型存在节选。不是无限记忆，也不保证被省略的每个细节都能召回。

## 验证

- Python 回归覆盖截图偏题、早期项目链接、换题隔离、80 轮上下文、超长节选、保存后恢复、模型规划输出校验、指定版本、双来源覆盖、搜索服务失败、正文读取、安全地址检查、两阶段计费和重复提交。
- JavaScript 回归使用实际前端函数，确认 80 轮记录不会被请求裁剪，并核对来源显示与链接转义。
- 真实公开网页测试使用数据库里的原始地址：`Tencent/WeKnora` 与 `Zleap-AI/SAG-Wiki/releases/tag/v0.2.7`。读取到 WeKnora README、SAG-Wiki v0.2.7 发布说明及该标签 README，未返回词典页面。该次测试约 8.3 秒；速度不是固定承诺。
- 外部网页测试未调用付费语言模型。规划、回答和计费链路使用隔离数据库与模拟上游验证，不能视为真实付费模型验收。

## 与 Claude Code、Codex 的关系

公开文档描述的是模型结合上下文选择工具、查看结果并继续核对的循环，不是固定的“一句话扔给搜索引擎”，也没有保证每轮都同时搜索所有平台。搜索负责找页面，网页读取负责取得正文；得到线索后需要检查是否支持结论。
