## 方法和结果

每个模块构造 26 轮长历史，在最早两轮埋入两个完整 GitHub 链接、错误地址的纠正、版本、受众、预算、部署与发布约束，以及两个自定义记忆标记。历史文本为测试数据，不是 26 轮逐次付费生成。摘要和最后的回答全部由真实模型生成。

首次压缩后，重新打开数据库连接，加入新的预算纠正及后续背景，扩展至 52 轮，再次压缩并提问。提问不包含答案。对实际发送的消息进行核对，关键链接、标记与最终预算只在摘要中，近期原文和当前提问均未重复这些答案。

## 用量与容量

共 21 次真实调用：15 次分批摘要、6 次回答。输入 136,002 Token，输出 8,247 Token；所有调用均返回用量，没有未知状态。按当前输入 2、输出 8 积分/百万 Token 折算，共 **0.337980 积分**，不代表生产工作台钱包被扣除该数额。

上游目录未声明该模型的真实上下文容量，因此本次使用工作台明确标注的默认 65,536，并以 UTF-8 字节保守估算触发；这不证明模型服务本身支持的最大容量。六次成功是本组样例结果，不代表任意长对话无损记忆。本次未生成 PPT 文件或海报图片，没有调用联网搜索、生图或公开发布。

## 保存位置和复核入口

聊天记录、原始历史、摘要和项目已有本地 SQLite 持久化，不需要额外创建另一份聊天日志。后台设置新增“聊天记录与存储”，显示服务实际使用的完整保存文件夹和数据库路径，管理员可选择复制。显示值来自实际运行配置，不硬编码盘符，也不执行迁移。

本机当前使用项目下 `.commercial-data/workspace.sqlite3`。如做备份，应先正常关闭本地工作台服务并复制整个 `.commercial-data`，其中也有项目、素材和服务连接配置。

验收脚本：`tests/manual_live_memory.py`，必须显式传入 `--run-live`，使用前应获得真实付费调用授权；单次保护预算为 2 积分，拒绝复用已有调用记录的输出目录，不自动重试。

本次本地原始证据保存在 `.workspace-data/qa/live-memory-20261113/run-01/`：`calls.json` 为用量记录；`call-*-input.json` / `call-*-output.json` 为完整请求消息与回复；`results.json` 保留初始匹配误报；`reviewed-results.json` 是离线复核结果。测试数据库与凭据均不进入交付包。
