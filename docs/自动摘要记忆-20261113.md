# 1.2.0 自动摘要记忆

## 行为与设计

AI 对话（含图片 Agent）、PPT 需求沟通/大纲/单页修改、海报沟通/设计方案接入同一个摘要模块。每轮先读取对应会话的持久摘要，追加尚未覆盖的原始对话；在容量内不重复压缩。达到阈值后，选用本轮模型将旧摘要与新增的较早对话合并，保留近期完整对话及当前消息。不是基于关键词抽取的“摘要”。

摘要字段包括目标、决定、纠正、约束、带来源/可信程度的事实和未解决事项。整理提示要求新用户纠正覆盖旧说法，保留关键版本、链接和数字，区分用户确认与 AI 建议。摘要仍可能遗漏细节，原始对话保留供回查；不承诺无损或无限上下文。

设计参考 [OpenAI Compaction 官方文档](https://developers.openai.com/api/docs/guides/compaction)：在容量阈值前整理上下文并携带状态继续。当前工作台连接的是兼容 Chat Completions 的多模型服务，因此采用可读 JSON 摘要，不依赖 Responses 专有的加密 compaction item，也不宣称与 Codex 内部实现完全相同。

## 容量与模型配置

- `cpa_models.context_window` 是每个模型单独的上下文容量；界面可维护，切换模型立即重新评估。已配置容量不会因普通修改被清空，改换上游模型时不沿用未经确认的旧容量。
- 导入目录支持 `context_window`、`context_length`、`max_model_len`。未返回容量时标明默认 65,536；不能把模型别名当作服务商容量证明。本次只读核查的 `gpt-6.1-terra` 目录没有提供容量。
- 输入以 UTF-8 字节加协议开销保守估计 Token，不是精确分词。触发预算为所选窗口的 80% 扣除最大回复及联网/视觉等预留。保留至少最近两轮完整对话，允许时保留更多；单轮加资料本身过大时明确要求减少资料或换大容量模型，不悄悄丢弃。
- 摘要请求也受同一窗口限制。很长的旧记录拆成稳定片段分批处理，每次有效摘要立即写入数据库检查点。只处理检查点之后的新增旧记录。

## 持久化、隔离与费用

`conversation_memory` 保存摘要、覆盖位置、前缀校验、修订号和原始历史快照。用户/模块/项目会话/话题决定记忆范围，AI 对话按 conversation 隔离；编辑或替换历史导致前缀变化时不复用不匹配的摘要。PPT 不同操作共用记忆，海报新建/切换对话携带独立且持久的会话 ID。

同一记忆范围的并发请求被阻止，避免讨论和大纲互相覆盖。重复请求号复用原结果，不重复调用或扣费。每次摘要调用的用量和上游请求号单独落库，最终与联网规划和回答一起结算；回答被明确拒绝仍按已完成的辅助调用结算。任一付费调用用量不明时保留预留额度待核对。摘要格式或容量不合格不覆盖上一份有效摘要。

## 验证范围

自动化测试使用隔离数据库和受控模型替身，覆盖多批压缩、重开数据库续用、增量、用户纠正传递、原文保留、模型切换、改写历史、新会话与用户隔离、PPT/海报共用、AI 对话流式路径、失败检查点、请求幂等和合并计费。联网相关与图片交付回归一并运行。

1.2.0 阶段使用受控模型替身验收；随后按用户授权，在 1.2.1 阶段使用当前配置的 gpt-6.1-terra 完成三处真实摘要与回答验证，详见 [真实长对话验收](真实长对话验收-20261113.md)。数据库迁移只新增表和列，原有账号、资料与项目保持原值。发布包不包含本地数据库、密钥或依赖环境。
